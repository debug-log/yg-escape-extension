# YG Escpae Extension

키이스케이프·플레이33의 예약 오픈 일정 확인과 날짜·시간 선택을 돕는 Chrome 확장 프로그램입니다. 사이트별로 시작하고 필요한 기능만 켤 수 있습니다. 고급 설정에서는 등록한 사이트의 XHR·fetch JSON 응답을 규칙에 따라 변경할 수 있습니다.

## 예약 오픈 안내

등록된 키이스케이프·플레이33 사이트에서 방문 날짜의 예약 오픈 일시를 표시합니다. 사이트별 **오픈 일정 안내**로 켜고 끌 수 있으며 기본 시간표·예약 선택 패널과 독립적으로 동작합니다.

- **키이스케이프:** 기존 달력의 크기와 선택 스타일을 유지하며 작은 표시와 두 줄 툴팁으로 오픈 정보를 안내합니다. 오늘 오픈을 앞둔 날짜에만 오픈 시각을 직접 표시합니다.
- **플레이33:** 예약 선택 변경 영역의 날짜 아래에 오픈 일시를 간결하게 표시합니다. 날짜를 비우거나 오픈 시각이 지나면 안내를 숨깁니다. 일반 예약 목록과 선택 패널을 끈 입력 페이지에서도 작은 안내를 사용할 수 있습니다.
- 모든 계산은 **한국시간(KST)** 기준입니다. 10분 미만은 초 단위, 그 이상은 시간·분 또는 일·시간으로 표시합니다.
- ‘오픈됨’은 오픈 예정 시각이 지났다는 뜻이며 **잔여석 확인 결과가 아닙니다**. 카운트다운 종료 시 자동 예약·제출·새로고침을 하지 않습니다.
- 규칙은 2026-11-03 공식 예약 화면 기준입니다. 키이스케이프는 선택 테마의 현재 달력 범위를 우선 적용하며, 플레이33 목록은 현재 페이지의 오픈 설정을 우선합니다. 에버랜드 등 확인되지 않은 지점은 확인 필요로 표시합니다. 기기 시계 오차와 운영 정책 변경은 반영되지 않을 수 있습니다.

변경 사항을 적용하려면 `chrome://extensions`에서 확장 프로그램을 새로고침한 뒤 예약 페이지를 새로고침하세요.

## 처음 설치하기 (Windows · macOS)

**ZIP 파일 다운로드 → 압축 풀기 → Chrome에 폴더 등록** 순서로 설치합니다. ZIP 파일을 더블클릭하거나 Chrome에 끌어다 놓는 것만으로는 설치되지 않습니다.

PC용 **Google Chrome 111 이상**이 필요합니다. 별도 프로그램 설치나 명령어 입력, npm 설치·빌드는 필요 없습니다.

### 1. 설치 파일 다운로드

1. [최신 버전 다운로드 페이지](https://github.com/debug-log/yg-escape-extension/releases/latest)를 엽니다.
2. 페이지 아래쪽의 **Assets**(첨부 파일 목록)를 찾습니다. 목록이 접혀 있으면 클릭해 펼칩니다.
3. **`yg-escape-extension-버전.zip`** 파일을 클릭해 다운로드합니다. 파일 이름의 `버전` 부분에는 실제 버전 번호가 들어갑니다.

> `Source code (zip)`은 소스 코드 묶음입니다. 설치 안내에서는 위 이름의 배포용 ZIP을 사용하세요. `.zip.sha256`은 파일 검증용이므로 설치할 때 내려받지 않아도 됩니다.

### 2. 압축을 풀고 보관할 폴더 정하기

Chrome은 압축을 푼 폴더의 파일을 계속 사용합니다. **설치한 뒤에도 이 폴더를 옮기거나 삭제하지 마세요.** 다운로드 폴더에 그대로 두기보다 문서 폴더처럼 계속 보관할 위치를 권장합니다.

**Windows**

1. 파일 탐색기에서 **다운로드** 폴더를 열고 받은 ZIP 파일을 찾습니다.
2. ZIP 파일을 마우스 오른쪽 버튼으로 클릭하고 **모두 압축 풀기**를 선택합니다.
3. 압축을 풀 위치를 문서 폴더 아래의 `YG-Escape-Extension`으로 지정하고 **압축 풀기**를 누릅니다.
4. 압축이 풀린 폴더를 열어 `manifest.json` 파일이 있는지 확인합니다. 파일 확장명을 숨기는 설정에서는 `manifest`로 보일 수 있습니다.

**macOS**

1. Finder에서 **다운로드** 폴더를 열고 받은 ZIP 파일을 찾습니다.
2. ZIP 파일을 더블클릭해 압축을 풉니다.
3. 생성된 폴더를 **문서** 폴더로 옮기고, 알아보기 쉽도록 이름을 `YG-Escape-Extension`으로 바꿉니다.
4. 폴더를 열어 `manifest.json` 파일이 있는지 확인합니다.

선택할 폴더는 다음처럼 `manifest.json`이 바로 들어 있는 폴더입니다. 폴더 안에 폴더가 한 번 더 있다면 안쪽으로 들어가 확인하세요.

```text
문서/
└─ YG-Escape-Extension/   ← 다음 단계에서 선택할 폴더
   ├─ manifest.json
   ├─ background.js
   ├─ popup.html
   └─ ...
```

### 3. Chrome에 확장 프로그램 등록

1. **Google Chrome**을 엽니다.
2. 화면 위쪽 **주소창**에 `chrome://extensions`를 입력하고 Enter를 누릅니다. 검색 사이트의 검색창이 아니라 웹사이트 주소가 표시되는 칸에 입력하세요.
3. 확장 프로그램 화면 오른쪽 위의 **개발자 모드** 스위치를 켭니다. 내려받은 폴더를 직접 등록할 수 있게 하는 설정입니다.
4. 왼쪽 위에 나타나는 **압축해제된 확장 프로그램을 로드합니다** 버튼을 누릅니다. 영어 화면에서는 **Load unpacked**입니다.
5. 앞에서 압축을 푼 `YG-Escape-Extension` 폴더를 선택하고 **폴더 선택** 또는 **선택** 버튼을 누릅니다.

> ZIP 파일이나 `manifest.json` 파일 자체가 아니라, **`manifest.json`이 들어 있는 폴더**를 선택하세요. 폴더 선택 창에서는 파일이 보이지 않을 수도 있습니다.

### 4. 설치 확인 및 아이콘 고정

1. 확장 프로그램 목록에 **YG Escpae Extension**이 나타나고 스위치가 켜져 있으면 설치된 것입니다.
2. Chrome 주소창 오른쪽의 **퍼즐 조각 모양 아이콘**(확장 프로그램)을 누릅니다.
3. **YG Escpae Extension** 옆의 **핀 아이콘**을 눌러 주소창 옆에 고정합니다.
4. 고정된 확장 아이콘을 누르면 작은 설정 창이 열립니다. 오른쪽 위의 **설정**을 누르면 사이트별 예약 도우미를 관리할 수 있습니다.

### 5. 처음 사용할 때

1. 확장 아이콘 → **설정 → 예약 도우미**를 엽니다.
2. 키이스케이프 또는 플레이33 카드에서 **사용 시작**을 누르고 Chrome이 요청하는 **사이트 접근 권한**을 허용합니다. 권한을 거절하면 설정은 바뀌지 않습니다.
3. 키이스케이프는 **오픈 일정 안내·날짜 선택 제한 해제·기본 시간표**, 플레이33은 **오픈 일정 안내·예약 선택 패널**이 함께 켜집니다. 켜진 항목은 화면에서 안내합니다.
4. 열려 있던 예약 페이지를 새로고침합니다. 이후에는 팝업에서 실제 적용 상태를 확인하고 **예약 페이지 새로고침**이 표시될 때 이용하세요.

설정의 **기능별 설정** 또는 예약 사이트에서 연 **팝업**에서 각 기능을 조정할 수 있습니다. 사이트 전체 스위치를 끄면 그 사이트의 예약 도우미만 중지합니다. 개별 기능과 테마별 선택은 유지되며 다시 켜면 복원됩니다. 두 사이트는 서로 독립적으로 동작합니다.

사이트 전체를 꺼도 직접 만든 사용자 응답 규칙과 개발자도구 방해 완화는 별도 설정을 따릅니다. 일반 사이트 등록·응답 규칙 만들기·개발자도구 방해 완화는 **설정 → 고급 설정**에서 관리하세요.

기존 설치는 업데이트만으로 기능을 새로 켜지 않습니다. 기존 응답 변경 스위치는 **사용자 응답 규칙 적용**으로 유지되고, 기존 기본 시간표의 켜짐 상태를 한 번 가져와 별도로 저장합니다. 이후 두 스위치는 서로 영향을 주지 않습니다. 이름·시간표·규칙 순서·개별 꺼짐 상태도 유지됩니다.

### 새 버전으로 업데이트하기

확장 아이콘을 누른 뒤 **업데이트**를 열어 안내를 따르세요. 처음에는 **설치 폴더 연결**에서 위에서 Chrome에 등록한 폴더를 지정하고 읽기·쓰기 권한을 허용해야 합니다. 자세한 절차와 복구 방법은 아래 [GitHub 자동 업데이트](#14-github-자동-업데이트)를 참고하세요.

수동으로 업데이트할 때는 **기존 확장을 제거하지 말고**, 같은 설치 폴더에 새 버전 파일을 덮어쓴 뒤 `chrome://extensions`의 **YG Escpae Extension 카드에 있는 새로고침 아이콘**을 누릅니다. 사용하던 웹페이지도 새로고침하세요. 다른 경로에 별도로 설치하면 설정 저장 공간이 달라질 수 있습니다.

### 설치가 잘 안 될 때

| 상황 | 확인할 내용 |
| --- | --- |
| 압축해제된 확장 프로그램을 로드하는 버튼이 안 보여요. | `chrome://extensions` 오른쪽 위의 **개발자 모드**가 켜져 있는지 확인하세요. |
| 매니페스트를 찾거나 읽을 수 없다는 오류가 나요. | ZIP의 압축을 먼저 풀었는지, 선택한 폴더 바로 안에 `manifest.json`이 있는지 확인하세요. 한 단계 바깥 폴더를 선택하지 않았는지도 확인하세요. |
| 설치했는데 아이콘이 안 보여요. | 주소창 오른쪽의 **퍼즐 조각 아이콘**을 눌러 확장 목록을 확인하고 핀으로 고정하세요. |
| 아이콘을 눌렀더니 웹페이지를 열라고 나와요. | 새 탭이나 Chrome 설정 화면 대신 실제로 사용할 웹사이트를 연 뒤 아이콘을 누르세요. |
| 설치했는데 기능이 적용되지 않아요. | 사이트 접근 권한을 허용했는지, 필요한 기능이 켜져 있는지 확인하고 대상 웹페이지를 새로고침하세요. **기본 시간표**는 해당 테마의 켜진 규칙과 요일별 시간표도 필요합니다. |
| 업데이트할 때 설치 폴더를 선택할 수 없어요. | 압축 파일이 아닌 실제 설치 폴더를 선택하세요. Windows의 `AppData`, `Program Files`, 시스템 폴더 등은 접근이 제한될 수 있으므로 처음 설치할 때 문서 폴더를 사용하세요. |
| 업데이트 중 Windows 보안에서 차단 알림이 떠요. | **Windows 보안 → 보호 기록**에서 차단 이유를 확인한 뒤 아래 안내에서 해당하는 방법을 따르세요. |

### Windows Defender가 업데이트를 차단할 때

먼저 시작 메뉴에서 **Windows 보안**을 검색해 열고 **바이러스 및 위협 방지 → 보호 기록**에서 차단된 항목의 설명과 파일 경로를 확인하세요. 바이러스 탐지와 보호된 폴더 접근 차단은 서로 다른 설정입니다. 차단됐다는 이유만으로 오탐이라고 단정할 수는 없으므로, 출처와 차단된 파일을 확인하고 신뢰하는 경우에만 예외를 추가하세요.

**바이러스·위협으로 탐지되는 경우: 설치 폴더를 검사 제외에 추가**

1. **Windows 보안 → 바이러스 및 위협 방지**를 엽니다.
2. **바이러스 및 위협 방지 설정 → 설정 관리**를 누릅니다.
3. 아래쪽의 **제외 → 제외 추가 또는 제거**를 누릅니다. 관리자 권한 확인이 나오면 확인합니다.
4. **제외 사항 추가 → 폴더**를 선택합니다.
5. Chrome에 등록했던 **`manifest.json`이 들어 있는 확장 프로그램 설치 폴더**를 선택합니다.

문서·다운로드 폴더 전체가 아닌 해당 확장 폴더만 지정하세요. 제외한 폴더의 파일은 Defender 검사에서 빠지므로 다른 파일을 함께 보관하지 마세요. 이미 격리되거나 삭제된 파일은 제외 설정만으로 복원되지 않습니다. 보호 기록에서 해당 항목의 상태를 확인하세요.

**“보호된 폴더 액세스 차단됨”이 표시되는 경우: 폴더 접근 허용**

문서 폴더 등이 랜섬웨어 방지 기능으로 보호되고 있으면 업데이트 파일 쓰기가 차단될 수 있습니다. 이 경우 위의 백신 검사 제외 설정과는 별도로 처리합니다.

1. **Windows 보안 → 바이러스 및 위협 방지 → 랜섬웨어 방지 관리**를 엽니다.
2. **제어된 폴더 액세스를 통해 앱 허용**을 누릅니다.
3. **허용된 앱 추가 → 최근에 차단된 앱**을 선택합니다.
4. 보호 기록의 차단된 앱이 실제 설치된 Google Chrome의 **`chrome.exe`**인지 경로를 확인한 뒤 해당 앱을 허용합니다. 이름만 같거나 출처를 모르는 앱은 허용하지 마세요.

이 설정은 해당 확장 폴더만이 아니라 보호된 폴더에 대한 Chrome의 접근을 허용합니다. 설정을 바꾼 뒤 업데이트 화면을 다시 열어 시도하세요. Defender 전체 실시간 보호나 랜섬웨어 방지 기능을 끌 필요는 없습니다.

설정 참고: [Microsoft 공식 Windows 보안 안내 — 제외 및 제어된 폴더 액세스](https://support.microsoft.com/ko-kr/windows/security/threat-malware-protection/virus-and-threat-protection-in-the-windows-security-app)

설치 방식 참고: [Chrome 공식 확장 프로그램 설치 안내](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked)

## 1.4.4 레드 테마

- [여기어때 Design Library](https://designlibrary.yeogi.com/brand/color)의 Yeogi Red를 참고해 팝업·설정·업데이트 화면을 흰색과 중립 회색, 빨간 포인트로 통일했습니다.
- 버튼과 제목의 글자 크기·굵기, 입력창과 카드의 간격을 정리했습니다. Windows는 맑은 고딕, macOS는 시스템 한글 서체를 사용해 별도 글꼴 설치 없이 표시합니다.
- 날짜 제한 해제 표시는 테두리 없이 아주 옅은 붉은 음영으로 표시됩니다.

## 1.4.3 규칙 정렬과 날짜 음영

- 고급 설정의 규칙 이름과 사이트를 분리하고, 편집·켜기/끄기·순서 이동·삭제 버튼을 같은 열에 정렬했습니다. 좁은 화면에서는 버튼이 다음 줄에 표시됩니다.
- 해제된 날짜의 점선 테두리를 은은한 녹색 배경 음영으로 바꿨습니다. 날짜 선택 배경색과 주말 글자색은 유지합니다.

## 1.4.2 새로고침 없는 날짜 전환

- 등록한 예약 페이지에서 날짜 자동 열기를 끄면 확장이 열었던 날짜와 표시를 즉시 복원합니다. 다시 켜면 현재 달력에 바로 적용합니다.
- 페이지를 다시 불러오지 않으므로 드롭다운에서 선택한 테마를 유지합니다. 최초 사이트 등록과 개발자도구 방해 완화의 새로고침 안내는 별개입니다.

## 1.4.1 해제된 날짜 구분

- 날짜 선택 제한을 해제한 칸에 주황색 점선 테두리와 마우스 안내를 표시합니다. 기존 날짜 선택 배경색은 유지합니다.
- 테스트와 패키징은 Python 3의 `python` 명령을 사용합니다.

## 1.4 GitHub 자동 업데이트

- 확장 아이콘을 열면 최신 안정 릴리스를 확인합니다. 확인 결과는 6시간 동안 재사용하고, **업데이트 → 다시 확인**으로 즉시 확인할 수 있습니다. 아직 릴리스가 없거나 인터넷에 연결되지 않아도 기존 기능은 유지됩니다.
- **설정 → 업데이트 → 설치 폴더 연결**에서 Chrome에 등록한 폴더를 선택하고 읽기·쓰기 권한을 허용합니다. 현재 실행 중인 설치 폴더인지 확인하므로 다른 사본은 거절합니다. Chrome이 권한을 다시 요청할 수 있습니다.
- **새 버전으로 업데이트**를 누르면 ZIP 다운로드, 파일 검증, 백업, 파일 교체, 확장 재시작을 진행합니다. 별도 프로그램이나 직접 압축 해제가 필요하지 않습니다. 업데이트 중에는 이 탭을 열어두세요.
- 저장된 규칙·사이트·스위치 상태를 유지합니다. **완료 후 원래 웹페이지 새로고침**을 선택하면 기존 페이지를 다시 불러옵니다. 그 사이 다른 주소로 이동했거나 탭을 닫았다면 해당 페이지는 새로고침하지 않습니다.
- 파일 교체가 실패하면 해당 파일만 건너뛰고 나머지는 계속 적용합니다. 자동으로 이전 버전으로 되돌리지 않습니다. 재시작 후 **일부 파일 미적용** 안내에 갱신하지 못한 파일만 표시하며, 팝업에서도 목록을 다시 열 수 있습니다.
- 안내의 **새 버전 다운로드**에서 ZIP을 받아 미적용 파일만 같은 설치 폴더에 덮어쓰고 확장을 새로고침하세요. **미적용 파일 다시 적용**을 누르면 배포본과 대조해 이미 일치하는 파일은 건너뛰고, 모두 확인되면 안내를 정리합니다. 보안 검사는 그대로 유지되므로 차단된 파일의 적용을 보장하지 않습니다.
- 백업은 수동 복구용으로 유지합니다. 중간에 탭이나 브라우저를 닫았다면 업데이트 설정에서 상태를 확인하세요. 파일 적용 후 재시작하지 못했다면 **적용한 버전으로 다시 시작**, 되돌리려면 **이전 파일 복구**를 누릅니다. manifest 변경까지 실패한 경우 실제 남아 있는 버전으로 재시작합니다.
- 기본 규칙 파일은 배포에 포함합니다. 개인 설정 백업과 조사 결과는 포함하지 않으며, GitHub에는 버전 확인·ZIP 다운로드 요청만 보냅니다.

**1.3.x에서 처음 옮길 때:** 기존 버전에는 업데이트 기능이 없으므로 1.4.0 이상 ZIP을 기존 설치 폴더에 한 번 덮어쓰고 `chrome://extensions`에서 확장을 새로고침해야 합니다. 이후 버전부터 업데이트 버튼을 사용할 수 있습니다. 기존 확장은 삭제하지 마세요.

**Windows:** ZIP을 브라우저에 직접 끌어넣지 말고 먼저 폴더에 압축을 풉니다. 예를 들어 사용자 문서 폴더 아래 `YG-Escape-Extension`을 만들고 해당 폴더를 개발자 모드로 등록합니다. Chrome은 `AppData`(임시 폴더 포함), `Program Files`, Windows 시스템 폴더 등의 접근을 제한하므로 해당 위치는 사용하지 마세요. 설치 후 폴더를 옮기지 마세요.

GitHub의 자동 생성 `Source code (zip)`은 업데이트용 파일이 아닙니다. `yg-escape-extension-버전.zip`을 사용하세요.

별도 npm 설치나 빌드는 필요 없습니다. Chrome 111 이상이 필요합니다.

## 1.3.1 기본 규칙 자동 설치와 팝업 설정

- 설치할 때 같은 요일 시간표 대체 규칙 **34개(공식 응답 표본 233개 + 사용자 제공 시간표 3개)**를 자동으로 불러옵니다. 기존 설치도 업데이트 후 최초 1회 빠진 규칙만 보충합니다. 같은 ID의 수정·꺼짐 상태와 개인 규칙, 전체 응답 변경 스위치는 유지합니다.
- 어둑시니(`31/96`)의 금·토·일은 2026-11-03에 사용자가 제공한 요일별 시간표를 사용합니다. 월~목은 공식 응답과 일치하며, 금·토·일은 공식 서버에서 재확인되지 않은 자료입니다. 각 표본의 `source`에 출처를 기록합니다. `date`의 2026-10-30·10-31·11-01은 같은 요일 검색을 위한 기준 날짜이며 실제 관측 날짜가 아닙니다. 요일별 `num`·`gubun`을 구분하고 기존 공식 성공 응답은 그대로 둡니다.
- 최초 보충 이후 직접 삭제한 규칙은 자동으로 다시 추가하지 않습니다. **설정 → 고급 설정 → 기본 규칙 복원**을 누르면 빠진 기본 규칙만 다시 추가합니다.
- 팝업에서 현재 사이트의 전체 도우미와 각 기능을 조정합니다. 개발자도구 방해 완화는 고급 설정에서 관리합니다. **사용 시작**이나 **기본 규칙 복원**은 필요한 사이트 접근 권한을 요청하며, 거절하면 설정은 변경하지 않습니다.
- 기본 규칙 저장과 사이트 권한은 별개입니다. **사용 시작**을 누르면 사이트를 등록하고 기본 시간표를 켭니다. 사용자 응답 규칙 적용은 별도이며 새 설치에서는 꺼져 있습니다.
- 확장과 예약 페이지를 새로고침하세요. 이미 열린 설정 탭도 새로고침하면 복원된 목록이 보입니다.

## 1.3 날짜 자동 열기

- 등록한 `https://keyescape.com/reservation1.php`의 최상위 페이지에서 날짜 자동 열기가 기본으로 켜집니다. 기존 사용자도 적용됩니다. 확장을 새로고침한 뒤 예약 페이지를 새로고침하세요.
- 전체 응답 변경 스위치나 테마 규칙과 독립적으로 동작합니다. `td.selDate.disabled[data-date]`의 `disabled`를 제거하고 `available`을 추가하며, 다른 클래스와 날짜 속성은 유지합니다.
- 월 이동이나 달력 재생성 후에도 적용합니다. 지난 날짜는 새로 열지 않으며, 테마별 저장 시간표가 일부 요일만 확인된 경우 미확인 요일도 선택 제한을 유지합니다. 확인된 같은 시간표 그룹은 함께 사용할 수 있습니다. 다른 사이트·경로·iframe에는 적용하지 않습니다.
- 확장이 선택 제한을 해제한 날짜는 은은한 붉은 배경 음영으로 구분합니다. 마우스를 올리면 해제된 날짜라는 설명이 표시됩니다.
- **예약 도우미 → 키이스케이프 → 기능별 설정 → 날짜 선택 제한 해제**에서 끌 수 있습니다. 끄거나 사이트를 해제하면 확장이 열었던 날짜와 표시를 즉시 복원합니다. 날짜 기능 전환에는 페이지 새로고침이 필요하지 않습니다.
- 팝업에서 날짜 자동 열기의 설정 상태와 적용 여부를 확인할 수 있습니다. 화면의 날짜 선택을 여는 기능이며 서버의 예약 가능 여부를 바꾸지는 않습니다.

## 1.2 개발자도구 방해 완화

기존 설치는 `chrome://extensions`에서 **YG Escpae Extension 새로고침**을 누르고 설정 탭과 대상 페이지를 새로고침하세요. 저장한 사이트와 규칙은 유지됩니다. 기존 **Anti Anti Debug는 끄고** 사용하세요. 두 확장을 동시에 켜면 같은 API를 중복 수정할 수 있습니다.

- 기존·신규 등록 사이트에서 방해 완화가 기본으로 켜집니다. **전체 응답 변경**을 꺼도 방해 완화는 유지됩니다.
- **고급 설정 → 등록한 사이트 → 개발자도구 방해 완화**에서 사이트별로 끌 수 있습니다. 설정 변경이나 사이트 삭제 후에는 대상 페이지를 새로고침하세요.
- 이 기능의 켜짐·꺼짐은 고급 설정에서 관리하며, 변경 후 대상 페이지를 새로고침합니다. 모든 탐지를 차단하는 기능은 아닙니다.
- 콘솔 지우기·표 출력을 막고, 함수·getter·특정 객체의 콘솔 출력을 가립니다. 정상적인 디버깅 출력도 일부 생략될 수 있습니다.
- `Function.prototype.constructor`로 생성하는 함수의 실제 `debugger` 문장만 제거합니다. 문자열·주석·정규식은 보존하며, 파싱할 수 없는 코드는 원본을 사용합니다.
- 권한이 있는 등록 사이트의 프레임에도 적용하지만, 미등록 교차 출처·다른 포트·`about:blank`·Worker에는 적용하지 않습니다. XHR 변환은 여전히 최상위 페이지에만 적용합니다.
- 설정 전달 전에 실행되는 탐지, 직접 작성된 `debugger`, 직접 `Function(...)` 호출, `eval`, 창 크기·시간·소스맵을 이용한 탐지는 지원 범위 밖입니다.

Anti Anti Debug 1.0.7의 방식을 참고했습니다. 원본 코드의 Unlicense와 로컬로 포함한 Acorn 8.15.0의 MIT 라이선스는 `vendor/`에 있습니다. 실행 중 외부 파서 다운로드나 별도 npm 설치는 없습니다.

## 키이스케이프 응답 규칙 템플릿

기존 설치는 `chrome://extensions`에서 YG Escpae Extension의 새로고침 버튼을 누르세요. 설정 탭과 대상 페이지도 새로고침하세요. 저장된 규칙은 유지됩니다.

1. 예약 페이지에서 확장 팝업 → **설정**을 누릅니다. 예약 페이지 주소가 자동으로 채워집니다.
2. **고급 설정 → 기본 템플릿 · 키이스케이프**에서 테마 이름과 할 일을 선택합니다.
3. **날짜 오류 응답 교체**는 해당 테마의 응답 JSON을 한 번 붙여넣습니다. **시간대 선택 상태 변경**은 JSON 입력이 필요 없습니다.
4. **변경 결과 확인**에서 시간대 개수·시간 범위·선택 가능 개수를 확인합니다.
5. **저장하고 켜기**를 누르고, 처음 등록한 사이트라면 Chrome의 권한 요청을 허용합니다. 예약 페이지를 새로고침하세요.

템플릿에서 저장하면 새 규칙을 목록 맨 앞에 배치합니다. 기존 규칙은 보존되므로 중복되는 규칙은 고급 설정에서 끄세요. 기본 시간표의 개별 테마는 **예약 도우미 → 키이스케이프 → 테마별 기본 시간표 관리**에서 검색하고 조정할 수 있습니다.

다른 테마나 다른 작업을 추가하려면 **새 설정 만들기**를 누르세요. 편집 중인 설정은 제목에 표시됩니다. 기존 설정 탭이 열린 상태에서 다른 페이지의 팝업을 열면 안내가 표시되며, **현재 페이지 사용**으로 새 설정을 시작할 수 있습니다.

키이스케이프 템플릿은 `zizum_num`, `theme_num`, 주소에 있는 경우 `theme_info_num`으로 페이지 범위를 제한합니다. 다른 테마의 응답 JSON은 저장 전에 거절합니다. 고급 편집에서도 범위가 표시되며 명시적으로 해제할 수 있습니다.

기존의 범용 규칙 편집과 요청 URL·메서드를 입력하는 미리보기는 **고급 설정**에 있습니다. 조건 불일치 시 어떤 사이트·URL·메서드·JSON 조건이 다른지 표시합니다. 전체 교체에서는 수정 목록이 숨겨집니다.

## 키이스케이프 예제

1. 사이트에 `https://keyescape.com`을 추가하고 Chrome의 사이트 접근 권한을 허용합니다.
2. 기본 제공되는 **예제: 시간대 enable 변경** 규칙을 켭니다.
3. 고급 설정에서 **사용자 응답 규칙 적용**을 켭니다.
4. 대상 페이지를 새로고침합니다. 팝업에서 **적용 준비 완료**를 확인합니다.
5. 날짜 선택 등으로 `run_proc.php` 조회를 다시 발생시킵니다.

예제는 `status`가 JSON boolean `true`인 응답에서 `data[*].enable`을 문자열 `"Y"`로 변경합니다. 날짜 오류 응답은 그대로 둡니다. 예제와 전체 스위치는 설치 시 꺼져 있습니다.

## 사용자 규칙

URL 비교는 전체 URL의 정확 일치 또는 문자열 포함입니다. HTTP 메서드 `ANY`는 모든 메서드를 뜻합니다.

조건 예시:

```json
[{"path":"status","op":"equals","value":true}]
```

경로 존재 여부는 `{"path":"data","op":"exists"}`로 검사합니다. 조건 배열 `[]`은 모든 JSON 응답에 일치합니다. 여러 조건은 AND이며, 배열 경로의 값은 하나라도 일치하면 됩니다.

필드 수정 예시:

```json
[{"path":"data[*].enable","value":"Y"}]
```

`data[0].enable`도 지원합니다. 없는 필드는 생성하지 않습니다. 점이 포함된 객체 키, 재귀 경로, 필터식은 지원하지 않습니다. 전체 교체를 선택하면 유효한 JSON 값을 입력합니다.

규칙은 목록 순서대로 검사하고 첫 번째 일치 규칙만 적용합니다. 규칙 활성화 여부와 무관하게 **미리보기**로 편집 중인 규칙 하나를 시험할 수 있습니다. 미리보기는 서버 요청을 보내지 않습니다.

## 적용 범위

- 일반 페이지의 `XMLHttpRequest`만 지원합니다. fetch, Worker, iframe에는 적용하지 않습니다.
- `responseType`이 빈 문자열, `text`, `json`이고 완료된 응답만 처리합니다. 바이너리, JSON 파싱 실패, 네트워크 오류는 원본을 유지합니다.
- 사이트 등록 직후에는 새로고침이 필요합니다. 초기 설정 전달 전 응답은 원본을 반환합니다.
- 설정 변경은 아직 변환 결과를 읽지 않은 요청부터 적용됩니다. 이미 반환한 결과는 해당 요청에서 일관되게 유지합니다.
- 전역 스위치를 끄거나 사이트를 삭제하면 이후 응답은 원본을 사용합니다. 완전한 후킹 제거는 새로고침 후 이루어집니다.
- Network 탭에는 원본 응답이 표시될 수 있습니다. 팝업의 변경 건수는 현재 페이지에서 실제 읽힌 변환 응답 수입니다.
- 사이트/다른 확장이 XHR이나 콘솔·함수 생성 API를 덮어쓰면 충돌할 수 있습니다. 개발자도구 방해 완화의 범위와 한계는 위 1.2 항목을 참고하세요.
- MAIN 실행 환경을 공유하므로 페이지는 후킹이나 전달된 규칙을 관찰·변조할 수 있습니다. 규칙에 비밀정보를 넣지 마세요. 페이지 메시지는 확장 설정 저장이나 권한 요청을 수행할 수 없습니다.
- 사이트 권한은 Chrome의 호스트 권한을 사용합니다. 저장된 사이트 origin으로 다시 필터링하므로 포트가 다른 페이지의 응답은 변경하지 않습니다.

## 검증

Node.js 24 이상과 Python 3가 필요합니다. 확장 실행 자체에는 Node/Python이 필요하지 않습니다.

```sh
npm test
npm run package
npm run test:update
node tests/browser-server.cjs
# 다른 터미널에서 실제 Chrome 자동 검증
node tests/run-chrome.cjs
# 별도 서버 없이 임시 프로필에 확장을 설치해 방해 완화 통합 검증
node tests/run-anti-debug-chrome.cjs
# 임시 확장과 가상 예약 페이지로 날짜 자동 열기 검증
node tests/run-date-unlock-chrome.cjs
# 선택: 실제 키이스케이프 페이지의 읽기 전용 시간 조회와 응답 교체 검증
XRE_TEST_LIVE=1 node tests/run-anti-debug-chrome.cjs
```

브라우저에서 `http://127.0.0.1:8765/tests/browser.html`을 열면 실제 Chrome XHR 동작을 검증합니다. 이 테스트는 확장을 설치하지 않고 동일한 엔진/후킹 코드를 로컬 페이지에 로드합니다.

단위 테스트: 규칙 매칭, 필드 수정, 전체 교체, 원본 보존, 설정 병합, 등록 오류 전달.
브라우저 테스트: 응답/이벤트 일관성, JSON 객체 동일성, 객체 재사용과 동시 요청, 오류 응답, 중단/타임아웃, 활성화 해제.

방해 완화 통합 테스트는 임시 확장 사본에 테스트 호스트 권한을 미리 부여합니다. 사용자의 기존 Chrome 프로필과 확장 설정은 변경하지 않습니다. 사이트 권한 승인/거부 UI와 기존 설치 프로필에서의 최종 사용 확인은 별도입니다. 실제 예약 전송은 테스트하지 않습니다.

업데이트 통합 테스트는 실제 Chrome·File System Access·IndexedDB를 사용하며, GitHub 응답만 테스트 배포본으로 대체합니다. 임시 프로필에서 폴더 권한을 미리 허용하므로 운영체제의 실제 폴더 선택·권한 승인 화면은 별도 수동 확인 대상입니다. `CHROME_PATH`로 Chrome 실행 경로를 지정할 수 있습니다.

## 플레이33 예약 선택 패널

`https://play33.kr/reservation/create`의 예약 폼 위에 지점·테마·날짜·시간 선택 패널을 표시합니다.

1. **설정 → 예약 도우미 → 플레이33 → 사용 시작**을 눌러 사이트 접근 권한을 허용합니다. 기본 테마·시간표 목록도 이 카드에서 확인할 수 있으며 별도 응답 규칙은 만들지 않습니다. 플레이33 웹페이지에서 팝업의 **사용 시작**으로 시작할 수도 있습니다.
2. 플레이33에서 시간대를 선택해 예약 정보 입력 페이지로 들어갑니다. 이미 열려 있다면 새로고침합니다.
3. **아래 예약 정보 변경**에서 선택하면 예약에 전달할 지점·테마·날짜·시간과 아래 예약일·테마명이 즉시 바뀝니다. 바뀐 항목 옆에는 **변경됨** 표시가 나타나며, 처음 값으로 복원하거나 기능을 끄면 원래 표시로 돌아갑니다. 응답 변경 스위치와 별개로 작동합니다.
4. **원래 값으로** 버튼으로 처음 페이지를 열었을 때의 값을 복원할 수 있습니다. 사이트 등록을 제거해도 패널이 사라지고, 패널에서 마지막으로 적용한 값이 유지된 경우 원래 값으로 복원합니다.

시간표는 2026년 11월 2~8일에 조사한 건대·홍대·대전·수원 10개 테마 기준입니다. 지점 변경 시 테마를 갱신하며, 날짜·테마 변경 후 기존 시간을 사용할 수 없으면 해당 시간표의 첫 시간을 선택합니다. 공휴일·실시간 예약 가능 여부는 반영하지 않습니다. 이름·연락처·인원·요금·안내는 변경하지 않으므로 원래 테마 기준으로 남습니다. 패널은 예약을 자동 제출하지 않습니다.

검증: `node --test tests/play33.test.cjs tests/background.test.cjs tests/bridge.test.cjs`, `node tests/run-play33-chrome.cjs`. Chrome 테스트는 임시 프로필의 확장과 가상 예약 폼을 사용합니다.

팝업의 **사용 시작**은 키이스케이프·플레이33의 기본 기능을 함께 켭니다. 다른 HTTP/HTTPS 사이트는 **고급 설정 → 등록한 사이트**에서 추가하고 **새 응답 규칙 만들기**로 규칙을 작성하세요. 사용자 응답 규칙 적용 스위치는 예약 도우미의 기본 시간표와 독립적입니다.

검증 명령:

```sh
npm test
node tests/run-helper-ux-chrome.cjs
node tests/run-date-unlock-chrome.cjs
node tests/run-play33-chrome.cjs
```

Chrome 통합 검사는 별도 임시 프로필과 테스트용 확장 사본을 사용합니다. 브라우저 위치가 다르면 `CHROME_PATH`를 지정하세요.

## 새 버전 배포

1. `manifest.json`의 버전을 올리고 변경 사항을 커밋합니다.
2. `npm test`와 `npm run test:update`로 검증합니다.
3. `main`에 반영한 뒤 해당 버전 태그를 올립니다. 예: `git tag v1.4.1` → `git push origin main v1.4.1`.
4. GitHub Actions가 Windows/Linux 테스트를 통과하면 필요한 실행 파일만 담은 ZIP과 SHA-256 파일을 Release에 게시합니다. 태그와 manifest 버전이 다르면 게시하지 않습니다.

업데이트 ZIP은 `scripts/package.py`의 명시적 파일 목록으로 생성합니다. 실행 파일을 추가할 때 이 목록도 갱신하세요. ZIP의 파일 목록과 해시를 모두 확인한 뒤 설치하고, `manifest.json`은 마지막에 기록합니다.
