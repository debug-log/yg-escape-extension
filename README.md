# YG Escpae Extension

Local Overrides 없이 등록한 사이트의 XHR JSON 응답을 조건에 따라 바꾸는 Chrome 확장 프로그램입니다. 서버 요청은 그대로 발생하고 페이지가 읽는 응답만 변경됩니다.

## 설치

1. Chrome 주소창에서 `chrome://extensions`를 엽니다.
2. 오른쪽 위 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**를 클릭합니다.
4. [최신 릴리스](https://github.com/debug-log/yg-escape-extension/releases/latest)의 `yg-escape-extension-버전.zip`을 내려받아 고정된 폴더에 압축을 풀고, `manifest.json`이 있는 폴더를 선택합니다.
5. 확장 프로그램 메뉴에서 **YG Escpae Extension → 규칙 관리**를 엽니다.

소스 저장소: https://github.com/debug-log/yg-escape-extension

기존 설치는 제거하지 않고 같은 폴더의 파일을 갱신한 뒤 새로고침해 사용하세요. 새 경로로 별도 설치하면 확장 ID와 설정 저장 공간이 달라질 수 있습니다.

## 1.4.2 새로고침 없는 날짜 전환

- 등록한 예약 페이지에서 날짜 자동 열기를 끄면 확장이 열었던 날짜와 표시를 즉시 복원합니다. 다시 켜면 현재 달력에 바로 적용합니다.
- 페이지를 다시 불러오지 않으므로 드롭다운에서 선택한 테마를 유지합니다. 최초 사이트 등록과 개발자도구 보호의 새로고침 안내는 별개입니다.

## 1.4.1 해제된 날짜 구분

- 날짜 선택 제한을 해제한 칸에 주황색 점선 테두리와 마우스 안내를 표시합니다. 기존 날짜 선택 배경색은 유지합니다.
- 테스트와 패키징은 Python 3의 `python` 명령을 사용합니다.

## 1.4 GitHub 자동 업데이트

- 확장 아이콘을 열면 최신 안정 릴리스를 확인합니다. 확인 결과는 6시간 동안 재사용하고, **업데이트 설정 → 새로 확인**으로 즉시 확인할 수 있습니다. 아직 릴리스가 없거나 인터넷에 연결되지 않아도 기존 기능은 유지됩니다.
- **규칙 관리 → 업데이트 설정 → 설치 폴더 선택**에서 Chrome에 등록한 폴더를 선택하고 읽기·쓰기 권한을 허용합니다. 현재 실행 중인 설치 폴더인지 확인하므로 다른 사본은 거절합니다. Chrome이 권한을 다시 요청할 수 있습니다.
- **새 버전으로 업데이트**를 누르면 ZIP 다운로드, 파일 검증, 백업, 파일 교체, 확장 재시작을 진행합니다. 별도 프로그램이나 직접 압축 해제가 필요하지 않습니다. 업데이트 중에는 이 탭을 열어두세요.
- 저장된 규칙·사이트·스위치 상태를 유지합니다. **완료 후 원래 웹페이지 새로고침**을 선택하면 기존 페이지를 다시 불러옵니다. 그 사이 다른 주소로 이동했거나 탭을 닫았다면 해당 페이지는 새로고침하지 않습니다.
- 파일 교체가 실패하면 이전 파일을 복구합니다. 중간에 탭이나 브라우저를 닫았다면 업데이트 설정에서 **이전 파일 복구**를 실행합니다. 파일 교체가 끝났지만 재시작하지 못했다면 **적용한 버전으로 다시 시작**을 누릅니다.
- 기본 규칙 파일은 배포에 포함합니다. 개인 설정 백업과 조사 결과는 포함하지 않으며, GitHub에는 버전 확인·ZIP 다운로드 요청만 보냅니다.

**1.3.x에서 처음 옮길 때:** 기존 버전에는 업데이트 기능이 없으므로 1.4.0 이상 ZIP을 기존 설치 폴더에 한 번 덮어쓰고 `chrome://extensions`에서 확장을 새로고침해야 합니다. 이후 버전부터 업데이트 버튼을 사용할 수 있습니다. 기존 확장은 삭제하지 마세요.

**Windows:** ZIP을 브라우저에 직접 끌어넣지 말고 먼저 폴더에 압축을 풉니다. 예를 들어 사용자 문서 폴더 아래 `YG-Escape-Extension`을 만들고 해당 폴더를 개발자 모드로 등록합니다. Chrome은 `AppData`(임시 폴더 포함), `Program Files`, Windows 시스템 폴더 등의 접근을 제한하므로 해당 위치는 사용하지 마세요. 설치 후 폴더를 옮기지 마세요.

GitHub의 자동 생성 `Source code (zip)`은 업데이트용 파일이 아닙니다. `yg-escape-extension-버전.zip`을 사용하세요.

별도 npm 설치나 빌드는 필요 없습니다. Chrome 111 이상이 필요합니다.

## 1.3.1 기본 규칙 자동 설치와 팝업 설정

- 설치할 때 같은 요일 시간표 대체 규칙 **34개(확인된 원본 시간표 215개)**를 자동으로 불러옵니다. 기존 설치도 업데이트 후 최초 1회 빠진 규칙만 보충합니다. 같은 ID의 수정·꺼짐 상태와 개인 규칙, 전체 응답 변경 스위치는 유지합니다.
- 최초 보충 이후 직접 삭제한 규칙은 자동으로 다시 추가하지 않습니다. **규칙 관리 → 고급 설정 → 기본 규칙 복원**을 누르면 빠진 기본 규칙만 다시 추가합니다.
- 팝업에서 **날짜 제한 해제**, **개발자도구 보호**를 바로 켜고 끌 수 있습니다. 미등록 사이트에서 켜거나 기본 규칙을 복원하면 Chrome의 사이트 접근 권한을 요청하고 등록합니다. 권한을 거절하면 설정은 변경하지 않습니다.
- 기본 규칙 저장과 사이트 권한은 별개입니다. 새 설치에서는 전체 응답 변경이 OFF이며, 사이트 권한을 허용하고 전체 응답 변경을 켜야 응답 교체가 적용됩니다.
- 확장과 예약 페이지를 새로고침하세요. 이미 열린 설정 탭도 새로고침하면 복원된 목록이 보입니다.

## 1.3 날짜 자동 열기

- 등록한 `https://keyescape.com/reservation1.php`의 최상위 페이지에서 날짜 자동 열기가 기본으로 켜집니다. 기존 사용자도 적용됩니다. 확장을 새로고침한 뒤 예약 페이지를 새로고침하세요.
- 전체 응답 변경 스위치나 테마 규칙과 독립적으로 동작합니다. `td.selDate.disabled[data-date]`의 `disabled`를 제거하고 `available`을 추가하며, 다른 클래스와 날짜 속성은 유지합니다.
- 월 이동이나 달력 재생성 후에도 적용합니다. 과거 날짜도 위 조건에 맞으면 열립니다. 다른 사이트·경로·iframe에는 적용하지 않습니다.
- 확장이 선택 제한을 해제한 날짜는 주황색 점선 테두리로 구분합니다. 마우스를 올리면 해제된 날짜라는 설명이 표시됩니다.
- **고급 설정 → 등록한 사이트 → 날짜 자동 열기**에서 끌 수 있습니다. 끄거나 사이트를 해제하면 확장이 열었던 날짜와 표시를 즉시 복원합니다. 날짜 기능 전환에는 페이지 새로고침이 필요하지 않습니다.
- 팝업에서 날짜 자동 열기의 설정 상태와 적용 여부를 확인할 수 있습니다. 화면의 날짜 선택을 여는 기능이며 서버의 예약 가능 여부를 바꾸지는 않습니다.

## 1.2 개발자도구 방해 완화

기존 설치는 `chrome://extensions`에서 **YG Escpae Extension 새로고침**을 누르고 설정 탭과 대상 페이지를 새로고침하세요. 저장한 사이트와 규칙은 유지됩니다. 기존 **Anti Anti Debug는 끄고** 사용하세요. 두 확장을 동시에 켜면 같은 API를 중복 수정할 수 있습니다.

- 기존·신규 등록 사이트에서 방해 완화가 기본으로 켜집니다. **전체 응답 변경**을 꺼도 방해 완화는 유지됩니다.
- **고급 설정 → 등록한 사이트 → 개발자도구 방해 완화**에서 사이트별로 끌 수 있습니다. 설정 변경이나 사이트 삭제 후에는 대상 페이지를 새로고침하세요.
- 팝업은 설정 켜짐·꺼짐, 새로고침 필요 여부를 표시합니다. ‘설정 반영됨’은 모든 탐지가 차단됐다는 뜻은 아닙니다.
- 콘솔 지우기·표 출력을 막고, 함수·getter·특정 객체의 콘솔 출력을 가립니다. 정상적인 디버깅 출력도 일부 생략될 수 있습니다.
- `Function.prototype.constructor`로 생성하는 함수의 실제 `debugger` 문장만 제거합니다. 문자열·주석·정규식은 보존하며, 파싱할 수 없는 코드는 원본을 사용합니다.
- 권한이 있는 등록 사이트의 프레임에도 적용하지만, 미등록 교차 출처·다른 포트·`about:blank`·Worker에는 적용하지 않습니다. XHR 변환은 여전히 최상위 페이지에만 적용합니다.
- 설정 전달 전에 실행되는 탐지, 직접 작성된 `debugger`, 직접 `Function(...)` 호출, `eval`, 창 크기·시간·소스맵을 이용한 탐지는 지원 범위 밖입니다.

Anti Anti Debug 1.0.7의 방식을 참고했습니다. 원본 코드의 Unlicense와 로컬로 포함한 Acorn 8.15.0의 MIT 라이선스는 `vendor/`에 있습니다. 실행 중 외부 파서 다운로드나 별도 npm 설치는 없습니다.

## 1.1 간편 설정 사용법

기존 설치는 `chrome://extensions`에서 YG Escpae Extension의 새로고침 버튼을 누르세요. 설정 탭과 대상 페이지도 새로고침하세요. 저장된 규칙은 유지됩니다.

1. 예약 페이지에서 확장 팝업 → **설정 변경**을 누릅니다. 예약 페이지 주소가 자동으로 채워집니다.
2. **간편 설정**에서 테마 이름과 할 일을 선택합니다.
3. **날짜 오류 응답 교체**는 해당 테마의 응답 JSON을 한 번 붙여넣습니다. **시간대 선택 상태 변경**은 JSON 입력이 필요 없습니다.
4. **변경 결과 확인**에서 시간대 개수·시간 범위·선택 가능 개수를 확인합니다.
5. **저장하고 켜기**를 누르고, 처음 등록한 사이트라면 Chrome의 권한 요청을 허용합니다. 예약 페이지를 새로고침하세요.

기존 JSON은 **저장한 설정 → 간편 설정으로 복사**로 가져올 수 있습니다. 주소와 테마 이름을 확인하고 저장하면 새 규칙을 목록 맨 앞에 배치합니다. 원래 규칙은 보존됩니다. 기존 규칙이 필요 없다면 고급 설정에서 끄세요.

다른 테마나 다른 작업을 추가하려면 **새 설정 만들기**를 누르세요. 편집 중인 설정은 제목에 표시됩니다. 기존 설정 탭이 열린 상태에서 다른 페이지의 팝업을 열면 안내가 표시되며, **현재 페이지 사용**으로 새 설정을 시작할 수 있습니다.

간편 설정은 `zizum_num`, `theme_num`, 주소에 있는 경우 `theme_info_num`으로 페이지 범위를 제한합니다. 다른 테마의 응답 JSON은 저장 전에 거절합니다. 고급 편집에서도 범위가 표시되며 명시적으로 해제할 수 있습니다.

기존의 범용 규칙 편집과 요청 URL·메서드를 입력하는 미리보기는 **고급 설정**에 있습니다. 조건 불일치 시 어떤 사이트·URL·메서드·JSON 조건이 다른지 표시합니다. 전체 교체에서는 수정 목록이 숨겨집니다.

## 키이스케이프 예제

1. 사이트에 `https://keyescape.com`을 추가하고 Chrome의 사이트 접근 권한을 허용합니다.
2. 기본 제공되는 **예제: 시간대 enable 변경** 규칙을 켭니다.
3. 팝업에서 **응답 변경 활성화**를 켭니다.
4. 대상 페이지를 새로고침합니다. 팝업에서 **적용 준비 완료**를 확인합니다.
5. 날짜 선택 등으로 `run_proc.php` 조회를 다시 발생시킵니다.

예제는 `status`가 JSON boolean `true`인 응답에서 `data[*].enable`을 문자열 `"Y"`로 변경합니다. 날짜 오류 응답은 그대로 둡니다. 예제와 전체 스위치는 설치 시 꺼져 있습니다.

## 사용자 규칙

URL 비교는 전체 URL의 정확 일치 또는 문자열 포함입니다. HTTP 메서드 `ANY`는 모든 메서드를 뜻합니다.

조건 예시:

```json
[{"path":"status","op":"equals","value":true}]
```

경로 존재 여부는 `{"path":"data","op":"exists"}`로 검사합니다. 조건 배열 `[]`은 모든 JSON 응답에 일치합니다. 여러 조건은 AND이며, 배열 경로의 값은 하나라도 일치하면 됩니다.

필드 수정 예시:

```json
[{"path":"data[*].enable","value":"Y"}]
```

`data[0].enable`도 지원합니다. 없는 필드는 생성하지 않습니다. 점이 포함된 객체 키, 재귀 경로, 필터식은 지원하지 않습니다. 전체 교체를 선택하면 유효한 JSON 값을 입력합니다.

규칙은 목록 순서대로 검사하고 첫 번째 일치 규칙만 적용합니다. 규칙 활성화 여부와 무관하게 **미리보기**로 편집 중인 규칙 하나를 시험할 수 있습니다. 미리보기는 서버 요청을 보내지 않습니다.

## 적용 범위

- 일반 페이지의 `XMLHttpRequest`만 지원합니다. fetch, Worker, iframe에는 적용하지 않습니다.
- `responseType`이 빈 문자열, `text`, `json`이고 완료된 응답만 처리합니다. 바이너리, JSON 파싱 실패, 네트워크 오류는 원본을 유지합니다.
- 사이트 등록 직후에는 새로고침이 필요합니다. 초기 설정 전달 전 응답은 원본을 반환합니다.
- 설정 변경은 아직 변환 결과를 읽지 않은 요청부터 적용됩니다. 이미 반환한 결과는 해당 요청에서 일관되게 유지합니다.
- 전역 스위치를 끄거나 사이트를 삭제하면 이후 응답은 원본을 사용합니다. 완전한 후킹 제거는 새로고침 후 이루어집니다.
- Network 탭에는 원본 응답이 표시될 수 있습니다. 팝업의 변경 건수는 현재 페이지에서 실제 읽힌 변환 응답 수입니다.
- 사이트/다른 확장이 XHR이나 콘솔·함수 생성 API를 덮어쓰면 충돌할 수 있습니다. 개발자도구 방해 완화의 범위와 한계는 위 1.2 항목을 참고하세요.
- MAIN 실행 환경을 공유하므로 페이지는 후킹이나 전달된 규칙을 관찰·변조할 수 있습니다. 규칙에 비밀정보를 넣지 마세요. 페이지 메시지는 확장 설정 저장이나 권한 요청을 수행할 수 없습니다.
- 사이트 권한은 Chrome의 호스트 권한을 사용합니다. 저장된 사이트 origin으로 다시 필터링하므로 포트가 다른 페이지의 응답은 변경하지 않습니다.

## 검증

Node.js 24 이상과 Python 3가 필요합니다. 확장 실행 자체에는 Node/Python이 필요하지 않습니다.

```sh
npm test
npm run package
npm run test:update
node tests/browser-server.cjs
# 다른 터미널에서 실제 Chrome 자동 검증
node tests/run-chrome.cjs
# 별도 서버 없이 임시 프로필에 확장을 설치해 방해 완화 통합 검증
node tests/run-anti-debug-chrome.cjs
# 임시 확장과 가상 예약 페이지로 날짜 자동 열기 검증
node tests/run-date-unlock-chrome.cjs
# 선택: 실제 키이스케이프 페이지의 읽기 전용 시간 조회와 응답 교체 검증
XRE_TEST_LIVE=1 node tests/run-anti-debug-chrome.cjs
```

브라우저에서 `http://127.0.0.1:8765/tests/browser.html`을 열면 실제 Chrome XHR 동작을 검증합니다. 이 테스트는 확장을 설치하지 않고 동일한 엔진/후킹 코드를 로컬 페이지에 로드합니다.

단위 테스트: 규칙 매칭, 필드 수정, 전체 교체, 원본 보존, 설정 병합, 등록 오류 전달.
브라우저 테스트: 응답/이벤트 일관성, JSON 객체 동일성, 객체 재사용과 동시 요청, 오류 응답, 중단/타임아웃, 활성화 해제.

방해 완화 통합 테스트는 임시 확장 사본에 테스트 호스트 권한을 미리 부여합니다. 사용자의 기존 Chrome 프로필과 확장 설정은 변경하지 않습니다. 사이트 권한 승인/거부 UI와 기존 설치 프로필에서의 최종 사용 확인은 별도입니다. 실제 예약 전송은 테스트하지 않습니다.

업데이트 통합 테스트는 실제 Chrome·File System Access·IndexedDB를 사용하며, GitHub 응답만 테스트 배포본으로 대체합니다. 임시 프로필에서 폴더 권한을 미리 허용하므로 운영체제의 실제 폴더 선택·권한 승인 화면은 별도 수동 확인 대상입니다. `CHROME_PATH`로 Chrome 실행 경로를 지정할 수 있습니다.

## 새 버전 배포

1. `manifest.json`의 버전을 올리고 변경 사항을 커밋합니다.
2. `npm test`와 `npm run test:update`로 검증합니다.
3. `main`에 반영한 뒤 해당 버전 태그를 올립니다. 예: `git tag v1.4.1` → `git push origin main v1.4.1`.
4. GitHub Actions가 Windows/Linux 테스트를 통과하면 필요한 실행 파일만 담은 ZIP과 SHA-256 파일을 Release에 게시합니다. 태그와 manifest 버전이 다르면 게시하지 않습니다.

업데이트 ZIP은 `scripts/package.py`의 명시적 파일 목록으로 생성합니다. 실행 파일을 추가할 때 이 목록도 갱신하세요. ZIP의 파일 목록과 해시를 모두 확인한 뒤 설치하고, `manifest.json`은 마지막에 기록합니다.
